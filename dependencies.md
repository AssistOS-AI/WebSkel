# WebSkel dependencies

## Runtime

WebSkel and `utils/uuid.mjs` add no third-party runtime dependency. UUIDv4
generation uses the browser's native `crypto.randomUUID()` or
`crypto.getRandomValues()`. Missing secure randomness fails with
`WEB_CRYPTO_UNAVAILABLE`; the application does not install a polyfill or weaken
randomness. Node.js 22.12+ is the development runtime prerequisite; validation
also runs on Node.js 24.21.0. The source tests use `node:test`, `node:assert`, and
`node:crypto`.

The source is maintained at https://github.com/AssistOS-AI/WebSkel. The root
`LICENSE` supplies the MIT copyright and license notice, which must accompany
redistributed source and bundles. The UUID compatibility changes and the
existing downstream loader/render/navigation fixes are maintained in source;
distribution files are generated by the existing build.

## Existing build toolchain

Vite is an existing development-only dependency. It preserves the project's
ESM/UMD build and tree shaking; hand-maintaining generated bundles is not an
acceptable replacement. No build dependency or version is added by the UUID
change. `package-lock.json` records the exact dependency tree, registry source
URLs, integrity hashes, and platform-specific optional packages. The installed
Linux build used the following locked packages:

| Package | Version | License | Purpose |
| --- | --- | --- | --- |
| vite | 7.1.2 | MIT | Existing library build and preview tool |
| rollup | 4.46.2 | MIT | Bundle ESM/UMD output |
| @rollup/rollup-linux-x64-gnu, @rollup/rollup-linux-x64-musl | 4.46.2 | MIT | Platform-specific Rollup binaries |
| esbuild, @esbuild/linux-x64 | 0.25.8 | MIT | Transform/minify source and load build configuration |
| @types/estree | 1.0.8 | MIT | Build-time syntax-tree declarations |
| fdir | 6.4.6 | MIT | Build file discovery |
| tinyglobby | 0.2.14 | MIT | Build file-pattern matching |
| picomatch | 4.0.3 | MIT | File-pattern matching |
| postcss | 8.5.6 | MIT | Existing stylesheet build pipeline |
| nanoid | 3.3.11 | MIT | Existing build-tool identifiers; not the browser UUID helper |
| picocolors | 1.1.1 | ISC | Build terminal formatting |
| source-map-js | 1.2.1 | BSD-3-Clause | Build source maps |

These packages resolve under `node_modules/<package>`; their package metadata
and license files remain with the installed dependencies. Upstream source and
update locations are recorded in each package's `package.json` repository field
and the lockfile's resolved URL. Platform alternatives remain optional and are
selected by npm; none is copied into the browser distribution as a new runtime
package by this change.

Install the existing locked toolchain with `npm ci`. Run `npm test` and
`npm run test:build`. A missing Vite installation stops the build with a
nonzero exit; there is no download during library initialization. To update
the toolchain, deliberately update the declared dev dependency and lockfile,
review licenses, and rerun source/build/consumer checks. Removing these build
dependencies requires replacing the existing ESM/UMD generation pipeline.
